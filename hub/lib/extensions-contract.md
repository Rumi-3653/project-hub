# 有料部品の接続口 v1（段階U1〜U6）

本体の入口は `extensions.js` だけ。登録一覧は `hub/paid/index.js`、各部品は
`{id, feature, version: 1, create(host), ui?}` を返す。`id` と `feature` は同じ固定名。
`create` に渡すホストの項目は固定し、本体の権限・所有確認・保存確定を回避しない。
話し合い・役割見直しでは既存の継続/停止/上限確認のフックも同じ入口を通す。
役割見直しの `heldLimit(request, limits)` は既存の上限判定を保つ任意フック。
部品がない時は本体の `limits.forRequest` を使い、無料会話の判定を維持する。
役割設定・変更履歴・デフォルト保存/復元は無料の本体に残す。

- `ui.script` / `ui.style` は `/paid/固定名.js` / `.css` のみ。起動時の内容を保持し、
  `/extensions-ui.js` / `.css` から同期読込する。操作画面の実装を公開側に残さない。
- 部品がない公開構成では、空のフック・空のUIを返す。有料APIは404と
  `feature_not_included`。無料の会話と既存履歴の表示は本体側に残す。
- 公式構成は `paid-bundle.json` で同梱予定を宣言する。部品一式がない場合は
  「有料部品が見つかりません」を状態・会話画面に示し、無料会話は継続する。
  存在する部品の文法不正・依存欠落・契約不一致・UI欠落は壊れた構成として起動を止める。
- 部品ありでも、話し合いの開始・手動まとめと役割見直しの開始には従来と同じ利用権検査を行う。
  基本会話無料、30日体験、31日目以降の有料機能制限、正当な利用コードは変更しない。
- 部品がない時の起動では、残った役割見直しを再起動による中断として記録し、
  その見直しの待ち指示と話し合いの待ち指示だけを既存の保存口で取り除く。
  通常の待ち指示は維持し、後始末の保存に失敗した時は起動を止める。
  部品がある時は従来の recover を使う。

## ローカルの組立入力

公開本体は `scripts/export-public.js` で保存済みcommitから抽出する。
`hub/paid/`、`hub/public/paid/`、`hub/paid-bundle.json` は出力しない。

公式アプリ用の入力は非公開側の `scripts/prepare-official.js --ref commit --output 新規フォルダ`
で作る。同じcommitの検査済み公開本体へ、私有部品の実行用ファイルと印だけを足す。
所有者版の印、発行者、鍵、台帳、依存部品、私有試験は足さない。
依存部品の準備後、そのフォルダの `hub/app/build-app.sh` で従来の1アプリを組み立てる。
公開リポジトリのCIは公開本体だけを組み立てる。公式用の準備処理は公開出力に含めない。
新たな配布・アップロード・署名認証・公開操作はこの準備処理に含まない。

## 今回の範囲と次

U1〜U5で話し合い・役割見直し・外部AI画面・依頼受け渡し・アイデア自動実行の
処理・画面を分離した。U6で残り3機能の判断と交代先の選択を差し込み口へ移した。
共有エンジンの移設はまだであり、完成した公開版として配布しない。
自動順番・上限交代・並行実行のエンジンは処理分割後。最後に残る画面を分割する。
Windowsの部品や試用物は今回更新せず、Mac/共通とWindowsのPRを分ける。

## U3 外部AI画面の境界

`webchat` は既存の Webchat/Client/固定guard と設定・進行UIを保持し、
既存ホスト（root/gpt/store/chat/assertIdle/onReply/onSettled/changed）を受ける。
利用権・停止の検査は従来と同じ本体のホストから渡す。外部送信/API設定/ログイン操作の実装は非公開側にある。
本体のSSEは世代確認と共通の作業中表示を渡し、外部ジョブの解釈・再取得は私有UIに任せる。
無料のMCP道具・設定・互換登録・作業権限と過去の会話表示は無料本体に残す。
部品なし時は外部操作API/送信を feature_not_included で拒否し、設定/モデル選択の操作は出さない。
保存された外部ジョブは読み込んで実行せず、ファイル自体も変更しない。無料の起動や会話を妨げない。
部品を戻した時は既存の再起動復旧により unknown/stopped にし、自動再送しない。


## 依頼の受け渡し（U4）

利用者向け `/api/delegate` の受付、利用権確認、委任カードとAI向けの案内は
`paid/delegate` に置く。追加の画面操作は無く、過去の受け渡し表示は無料本体に残す。
本体の `request-delivery.js` は送信・待ち列・監査の共有基盤であり、取り込みの整理・確認と
履歴整理は部品も利用権も不要。内部起点はサーバーが `hub-internal` を設定する。
HTTPからこの起点は指定できず、内部の待ち指示は編集・追加指示へ転用できない。
内部待ち列に伴うqueue_autoだけは課さず、別の有料機能（並行・上限交代・外部画面・
アイデア自動実行）の利用権は維持する。アイデア自動実行は無料内部起点にしない。

起動時、旧delegate待ち列のうちサーバーだけが保存できた整理/確認メタデータを持つものは
内部起点へ移行し、既存の実行直前検証を維持する。部品欠落時の利用者delegate待ち指示は
既存の耐久保存口で列から外す。会話原文・委任監査・統合の受領証拠は消さない。
内部か判別できない旧依頼は自動的に無料へ格上げしない。部品なし時の利用者委任は、
待ち列や継続から新たに開始する前にもガードで拒否する。既に起動済みで監督から
引き継いだ処理は、新しい開始とせず終了・保存まで監視する既存の方針を保つ。


## アイデアの自動実行（U5）

`idea_automation` は runner/dispatch/検証/審査/反映準備と操作UIを保持する。
ホストは ideas/store/baseOf/executionGate/chats/ROOT/rolesData/DRY/
delegateRequest/gitw/stopControl/webchatActive/sessions/record に固定する。
既存の delegate 起点・idea_automation の利用権と停止優先順は本体の同じ検査を使う。
無料の台帳・画像・一覧・削除・並替・手動の変更と受領証拠は本体に残す。
保存した「作る予定」は実行指示ではなく、部品なしでは自動実行しない。

欠落時は旧台帳の自動進行だけを停止し、原文・実行・審査・反映の証拠は保持する。
待ち列は automation.kind=idea の指示だけを除き、通常・内部依頼は維持する。
既に送信済みの監督引継ぎは元の場所・所有・依頼文を照合して終了ログを保存する。
その結果を解釈して次へ進めることはせず、有料部品を戻すまで記録を保持する。
残った検証子の終了を証明できない時は既存の実行ゲートで保留し、成功へ格上げしない。
新しい自動開始・継続は feature_not_included、操作UIは読み込まない。
公開本体は受領済み実行を安全に監視する読取専用の場所/証拠照合と検証復旧だけを持ち、
役割選択・AI文面生成・送信・検証コマンド実行・自動審査/反映は持たない。
残り3つの判断はU6で分離し、共有エンジンは処理分割後に移す。


## 実行判断3つ（U6）

`queue_auto`・`limit_switch`・`parallel` は版1の判断部品で、`features(options, active)`
から既存と同じ順序で必要な利用権を返す。License.guard は従来の位置でまとめて
require し、その後に部品欠落も同じ license_held（開始時だけ licenseHeld）として拒否する。
公開本体の欠落フックには、禁止操作を特定する否定専用の条件だけを残す。
有効な利用権や製作者モードがあっても、部品の無い操作は許可しない。
利用権の codec/status/30日体験・31日以降/購入判定そのものは変更しない。

`limit_switch` の enabled/backup は、既存の require → 対象除外 → 保存済み役割 →
最新main/backup → 特殊モード → アカウント/許可指定の順序を保つ。
モデル混雑の一回限定・対象モデル限定も同じ部品に移す。ホストは read-only の
license.require/rolesData/modelView.special/discussionRuntime/integrationPolicyRequest/
store.readProject/accountFor/permCmd に固定する。欠落時は enabled=false、backup=null。
上限検出と保存済み欄の同定、待ち列の保存/手動操作/取消/停止、同時セッションの
エンジンは本体に残す。仕組み3つの移設は処理分割後であり、U6で完了とはしない。
U4の無料内部依頼は従来どおりサーバー側で queue_auto だけを除外し、交代と並行の
制限は残す。欠落時に待ち列を消したり、自動で再送したりしない。
