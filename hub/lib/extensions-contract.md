# 有料部品の接続口 v1（段階U1/U2）

本体の入口は `extensions.js` だけ。登録一覧は `hub/paid/index.js`、各部品は
`{id, feature, version: 1, create(host), ui?}` を返す。`id` と `feature` は同じ固定名。
`create` に渡すホストの項目は固定し、本体の権限・所有確認・保存確定を回避しない。
話し合い・役割見直しでは既存の継続/停止/上限確認のフックも同じ入口を通す。
役割見直しの `heldLimit(request, limits)` は既存の上限判定を保つ任意フック。
部品がない時は本体の `limits.forRequest` を使い、無料会話の判定を維持する。
役割設定・変更履歴・デフォルト保存/復元は無料の本体に残す。

- `ui.script` / `ui.style` は `/paid/固定名.js` / `.css` のみ。起動時の内容を保持し、
  `/extensions-ui.js` / `.css` から同期読込する。操作画面の実装を公開側に残さない。
- 部品がない公開構成では、空のフック・空のUIを返す。有料APIは404と
  `feature_not_included`。無料の会話と既存履歴の表示は本体側に残す。
- 公式構成は `paid-bundle.json` で同梱予定を宣言する。部品一式がない場合は
  「有料部品が見つかりません」を状態・会話画面に示し、無料会話は継続する。
  存在する部品の文法不正・依存欠落・契約不一致・UI欠落は壊れた構成として起動を止める。
- 部品ありでも、話し合いの開始・手動まとめと役割見直しの開始には従来と同じ利用権検査を行う。
  基本会話無料、30日体験、31日目以降の有料機能制限、正当な利用コードは変更しない。
- 部品がない時の起動では、残った役割見直しを再起動による中断として記録し、
  その見直しの待ち指示と話し合いの待ち指示だけを既存の保存口で取り除く。
  通常の待ち指示は維持し、後始末の保存に失敗した時は起動を止める。
  部品がある時は従来の recover を使う。

## ローカルの組立入力

公開本体は `scripts/export-public.js` で保存済みcommitから抽出する。
`hub/paid/`、`hub/public/paid/`、`hub/paid-bundle.json` は出力しない。

公式アプリ用の入力は非公開側の `scripts/prepare-official.js --ref commit --output 新規フォルダ`
で作る。同じcommitの検査済み公開本体へ、私有部品の実行用ファイルと印だけを足す。
所有者版の印、発行者、鍵、台帳、依存部品、私有試験は足さない。
依存部品の準備後、そのフォルダの `hub/app/build-app.sh` で従来の1アプリを組み立てる。
公開リポジトリのCIは公開本体だけを組み立てる。公式用の準備処理は公開出力に含めない。
新たな配布・アップロード・署名認証・公開操作はこの準備処理に含まない。

## 今回の範囲と次

U1の話し合いに続き、U2で役割見直しの処理・画面を分離した。残り6有料機能は既存の利用権制御を保ったまま、
承認済み順序で今後移す。したがって現時点では「8機能すべてが公開本体から除外済み」
ではなく、完成した公開版として配布しない。
次は外部AI画面→外部への受け渡し→アイデアの自動実行→3機能の判断。
自動順番・上限交代・並行実行のエンジンは処理分割後。最後に残る画面を分割する。
Windowsの部品や試用物は今回更新せず、Mac/共通とWindowsのPRを分ける。
