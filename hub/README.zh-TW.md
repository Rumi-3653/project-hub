# Project Hub

本文件是 [日文使用說明](README.md) 的繁體中文版，主要說明從原始碼建立、啟動及更新的方式，以 Mac 為主。若要使用已封裝的應用程式，請從 [GitHub 發佈頁](https://github.com/kieiken/project-hub/releases) 取得適合系統的安裝用 ZIP；不要將下方的原始碼更新流程當成配布版的更新步驟。文件描述所依據的原始碼，不代表未公開的下一版已經發佈。

Windows 11 x64 的有限試用，請先閱讀 [Windows 專用視窗說明（日文）](app/windows/README.md)，並以一般使用者權限啟動。Windows 尚未支援的功能與儲存方式限制也列在該文件中。

對於使用者已停止、尚未接收的整合作業，若能確認停止與傳送的原始紀錄，可從［中止並重新選擇（日文：中止して選び直す）］確認對象，再確定中止。子作業、對話、工作副本、交付紀錄與主資料夾的暫存紀錄都會保留。中止不等於接收；結果不明或已有後續請求時，不能中止。

[選用的繁體中文語言包說明](../langpacks/zh-TW/README.md) — 未設定語言或沒有語言包時，使用日文。部分畫面可能仍保留日文；找不到繁體中文按鈕時，請對照日文說明。

在設定的「基本」→「語言」，按［新增語言包…］匯入已解壓縮的資料夾，選擇顯示語言並按［儲存］。按［立即重新啟動］即可切換（對話中的 CLI 會交接；終端機、儲存與整合程序則等待結束）。Mac 應用程式的選單要關閉並重新開啟 App 才會切換。若［刪除］正在使用的語言包，也會同時儲存改回日文的設定。

語言選項來自有效的語言包，不是固定清單。隨附的 `langpacks/<id>/` 與新增位置 `_hub/langpacks/<id>/`，資料夾名稱必須與 `pack.json` 的 `id` 一致。日文內建於主程式。
`pack.json` 的選用欄位 `dateLocale` 指定日期顯示的語言（省略時使用 `id`）。`backend.json` 的選用欄位 `headings` 只能指定「手順、やったこと、次にやること、注意、メモ」（步驟、已完成事項、接下來要做的事、注意事項、備註）這五種標題。沒有翻譯的句子或無效的語言包會回到日文。既有繁體中文標題仍可讀寫。不會將 CSS 或程式碼匯入為語言包。

語言包經文字資料檢查後，儲存在專案紀錄的 `_hub/langpacks/`；語言設定儲存在 `_hub/language.json`。損壞的語言包不會被接受，啟動時無法使用的語言包會改回日文。已儲存的語言優先於 `HUB_LANG`；沒有儲存設定時，仍可用 `HUB_LANG=zh-TW` 啟動。不會自動下載，也不直接匯入 ZIP。

一般作業的［摘要後繼續］，一次操作就會依序完成內部確認、摘要、保存原文及切換對話。該作業的 AI 執行中時不會開始，對話底部會提示結束後再操作；不會因父作業、子作業或其他作業的 AI 而阻擋。可從［過去的對話］查看對話與本文原文。整理結果最前方顯示「接下來要做的工作」，優先採用最新紀錄、排除已完成與重複項目，並區分等待判斷、沒有剩餘工作與紀錄不足。更新後會偵測啟動狀態的變化、保存草稿，並自動更新仍開著的畫面。

目前版本可查看 `package.json` 的 version（畫面左上方也會顯示）。變更紀錄見 [CHANGELOG.md（日文）](CHANGELOG.md)。

要將文字交給其他 AI 時，可用程式碼框的［⧉ 複製］複製本文。AI 以引用格式回覆時，也可按［⧉ 複製引用］，複製只移除最外層一層引用符號的原文。仍在生成的引用不顯示按鈕。

設定 ChatGPT（Chat／Pro）時，輸入另外安裝的 WebChatMCP 資料夾，按［登入］或［確認狀態］確認登入與臨時聊天狀態，再啟用並儲存。若要指定模型與思考程度，請從取得的清單選擇；未指定時使用 ChatGPT 目前設定。淡色路徑是輸入範例，僅整合 Hub 或儲存設定不會安裝外部軟體。

Project Hub 是列出專案與作業，並在畫面中執行 Claude Code／Codex 的管理工具，供單人在自己的 Mac 上使用。使用前請閱讀「使用前須知」。

子作業成果從［整合…］接收。為各子作業選擇［保留／不保留］後，按［整合］、［選擇性整合］或［批次整合］，即可從必要的整理與確認進行到接收及收尾。未完成事項會交接到主作業；保留接收或中途接收的子作業，會沿用［保留］選項。

只要接收勾選［選取］的作業，請按［選擇性整合（項數）］。在同一畫面重新確認或變更［保留／不保留］時仍保留選取，關閉後才清除。不會自動加入後代作業。若父作業選［不保留］，必須一併選取所有後代並設為［不保留］，否則請將父作業設為［保留］。未選取任何項目時不能執行。

## 第一次使用（只需一次）

必要條件：Node.js 22 以上、Git。先安裝要使用的 AI CLI（Claude Code／Codex）並登入。也需要 Apple 開發工具；若未安裝，setup.sh 會顯示安裝視窗後停止，安裝完成再執行一次。

進入取得的資料夾，在最上層（包含 `hub/` 的位置）執行。將 `<取得したフォルダ>` 換成實際下載路徑：

```
cd "<取得したフォルダ>"
bash hub/setup.sh
```

- 可以重複執行。
- 在 `~/Documents/AI-Workspace/` 建立 `_hub/`（角色分工 `roles.yaml`）、`Product/`（專案紀錄）及 `Work/`（工作副本）。可用 `HUB_ROOT` 改變位置；不修改既有 roles.yaml 與專案紀錄。
- 將 `hub/seed/` 的虛構範例紀錄複製到 `Product/`，不是實際專案或作業紀錄。請依自己的環境調整範例資料夾路徑。
- 透過 npm 安裝作業畫面的元件 node-pty。即使安裝失敗，管理工具仍可執行，作業會另開視窗。
- 桌面會出現「Project Hub」。

## 使用前須知

- **供單人 Mac 使用**：主程式只監聽 `127.0.0.1:4545`。會檢查 Host 與 Origin，但沒有使用者認證。不要將它作為公開 Web 服務或共用伺服器散布或執行。
- **AI 權限確認**：預設以 `--dangerously-skip-permissions` 啟動 Claude Code，以 `--dangerously-bypass-approvals-and-sandbox` 啟動 Codex（`lib/launch.js`）。Claude Code 會略過權限確認；Codex 會略過權限確認與沙箱。AI 能以使用者權限修改檔案、執行指令。若要改變，請在 `_hub/roles.yaml` 的 `permissions` 指定啟動方式。
- **會複製的設定**：建立工作副本時，會將主資料夾最上層尚未納入 Git 的 `.env`、`.env.*`、`.dev.vars`、`.dev.vars.*`、`.npmrc` 與 `.claude/settings.local.json` 一併複製，供 AI 執行測試。
- **自動 Git 儲存**：作業前儲存、首次儲存及整合工作副本時，會先執行 `git add -A` 再提交。提交時不顯示終端機確認，並使用 `--no-verify`，因此不執行 pre-commit 等 hook。Git 未設定姓名時，以 `Project Hub <hub@localhost>` 儲存。
  - 新增的 `.env` 類、`.npmrc`、`.dev.vars` 類及 `.claude/settings.local.json` 不會納入儲存；即使事先手動 `git add`，新增的這些檔案也會被排除，但檔案仍留在本機。範例用的 `.env.example`、`.env.sample` 會儲存。
  - 已納入 Git 的檔案、未經 Hub 手動提交的內容，以及其他名稱的機密檔案不在保護範圍。不保證機密不會進入紀錄；必要時請在各專案的 `.gitignore` 排除。
- **留在本機的紀錄**：對話 `.ai/chat/`、交接資料 `.ai/handoff/`、操作紀錄 `_hub/log.jsonl`、交付檔案 `AI-Workspace/Inbox/hub/`，都以未加密形式保存。既有 Git 專案的對話與交接也可能隨自動儲存進入歷史；若要排除，請寫入各專案的 `.gitignore`。新專案範本已附排除規則。分享或公開前，請先檢查內容。
- **費用**：實際使用 AI 的費用依各 AI CLI 的方案、費率與登入設定決定。Hub 不保證使用 AI 不會產生費用。
- **對外傳送**：將作業內容傳給第三方服務的操作（公開、發文、傳送等），以使用者每次另行核准後才執行為前提，不能以 Hub 的機制作為核准。

## 每次使用

連按兩下桌面的「Project Hub.app」，就會在專用視窗開啟，不需要終端機。第一次詢問「存取文件資料夾」時，請選擇「允許」。

- App（`app/window.swift`）會自行啟動主程式（node server.js），並用 Mac 內建 WebKit 顯示畫面。
- 關閉視窗後，主程式與工作中的 AI 仍會在背景執行；下次開啟可繼續查看。
- 失敗原因顯示在視窗中。紀錄位於 `~/Library/Logs/ProjectHub.log`（選單中的「開啟紀錄」）。
- `app/build-app.sh` 會重建 App（setup.sh 也會呼叫）。更新原始碼後請執行它。
- 重新命名等輸入對話框也可用 ⌘V 貼上。包含此項修正的更新，除了切換 Hub 主程式版本，也要重建 Mac App。
- 若要從終端機啟動，執行 `bash start.command`。

## 可以做什麼

- **特殊模式**：在設定［AI］啟用或停用，並指定 Claude Code／Codex。可在重設前或使用票券時集中由選定 AI 工作。本次請求明確指定 AI、模型或手動選取時，僅本次優先，下次回到特殊模式。同一 AI 內的模型與思考可由 AI 選擇。一般角色分工不變，執行中的 AI 與已受理的排隊指示也不變。達到上限時不自動切換其他 AI，而是等待解除。
- **檔案與資料夾連結**：點選後可選擇開啟方式。檔案可［開啟原始檔案］或［在 Finder 顯示］；資料夾可［在 Finder 開啟］或［查看內容］。直接使用原始位置，不下載副本。適用於 Mac App 與 Mac 瀏覽器。
- **整理與運作檢查**：顯示候選項目取得狀態，選取後可［移到垃圾桶］，也可從整理紀錄還原。取消取得時顯示原因。結構檢查會以專案位置為基準確認資料的相對路徑。
- **左側樹狀清單**：專案下方列出作業。分支作業（有來源作業）與子專案會縮排一層並標示「↳」；「⑂2」表示分支數量。
- **概要畫面**（點選專案）：顯示說明、作業清單、階段與負責人、問題及相關專案。［查看檔案］可開啟內容所在位置，若有多處則先選擇。
- **對話畫面**（作業畫面的［對話］，平常使用此處）：類似 Goose，在同一條對話中，每次傳送都能選擇回覆的 AI、模型與思考程度。回覆有負責 AI 標記。切換 AI 時，會一併交接該 AI 尚未看過的人與 AI 的文字對話；同一 AI 繼續時則恢復其原有會話。對話儲存在 `.ai/chat/<作業ID>.jsonl`。內部每次執行一次 `claude -p --output-format stream-json` 或 `codex exec --json`（`lib/chat.js`）。想看詳細進度時，切到［終端機］。
- **專案圓點**：灰色＝未開始；紅色＝AI 工作中；淺綠色＝處理結束；紫色＝完成（只有在專案畫面按［將專案標記為完成］才會變紫色，可［取消完成］）。下方作業圓點使用相同顏色，黃色表示需要你的回覆。
- **位置與 URL**：點選對話或問題中有 📁 的路徑，資料夾會在畫面內列出內容，檔案由對應 App 開啟，也可選［在 Finder 開啟］。URL 點選後在瀏覽器開啟，⧉ 可複製。
- **詳細操作**：指令等細節預設不顯示於對話，可在設定的「對話畫面」開啟。
- **檔案權限**：無法讀取文件等資料夾時，在設定或 App 選單按［重新顯示確認］，在 Mac 提示中選「允許」。沒有提示時，請加入「完整磁碟存取權限」。
- **AI 的問題**：AI 在對話中詢問判斷時，會顯示選項按鈕。點選即可傳送回答，作業狀態會變成黃色的等待回覆。
- **模型清單**：只顯示 CLI 回報目前可用的模型。可在設定「模型選單顯示項目」隱藏項目；［整理為最新模型］可更新角色中舊的模型名稱。
- **AI 交接給 AI**：AI 必須透過 Hub 的 /api/delegate 委派，在同一作業、同一對話切換負責 AI；若已有 AI 執行中，就排到結束後。沒有新增子作業，可在畫面確認順序、執行中的 AI 與模型，以及結果。委派須明確指定 model 或主要負責角色 role，也可使用正式名稱（如 claude-fable-5-1）；未指定或不可用時，回傳原因並停止。終端機執行中不能委派，會提示在同一作業的對話畫面繼續。啟動失敗不會清除狀態或問題；已完成作業要由使用者恢復後才能委派。未經 Hub 在背景啟動的 AI 也會被監看，並顯示「背景作業中」。
- **子專案**：用［拆成子專案］同時開始。子專案完成後，結果會進入父作業與對話並標示「新」。子專案尚在進行時若要推進父作業，會提出提醒。
- **接收中途成果**：尚未完成的子作業也可用［交付成果（中途）］，將已儲存成果交給父作業的［整合…］。須等 AI、整理與排隊指示停止並儲存變更後，再確認內容。中途接收會保留子作業對話、副本、剩餘步驟與問題，之後可再次接收新的儲存內容或成果。只有已完成子作業最後的［整合並清理］會收尾。
- **ChatGPT（Chat／Pro）**：設定外部 WebChatMCP，確認登入與臨時聊天後，在作業畫面選取並按［傳送］即可自動傳送。回覆儲存在原本的同一對話。不建立子作業或專用副本，也不修改檔案或執行指令。同一對話有其他 AI 或整理程序執行中時無法選取，請等結束。預設停用，需要另外安裝外部軟體並由本人登入。未指定模型與思考時使用 ChatGPT 現有設定；無法確認指定設定時會停止。停止、逾時或重新啟動後不自動重送。以前的 GPT 專用子作業與對話仍保留為紀錄。
- **從外部使用（iPhone）**：在設定啟用並設定通關密語。Mac 與 iPhone 安裝 Tailscale，在 Mac 執行 `tailscale serve --bg 4545`。iPhone 開啟 `https://<Macの名前>.<tailnet>.ts.net`（將佔位文字換成 Mac 名稱與 tailnet），輸入通關密語。登入後可進行與 Mac 相同的操作，程序在連線的 Mac 上執行。
- **未讀與 GitHub**：未查看時 AI 完成工作，左側清單會顯示「未讀」，開啟該作業對話後消失。已整合並整理的作業通知也會消失；已完成但未讀的作業會留在左側直到閱讀。主資料夾在 GitHub 時可按［GitHub］開啟，工作副本則開啟其分支。
- **快速開始**：在專案畫面寫下想做的事，按［開始］，就會建立作業並在對話畫面傳給 AI。左欄可選負責 AI、模型與思考。各專案記住上次的 AI，首次使用 Claude Code。文字與附圖在重新繪製、切換、重新啟動後仍保留，傳送成功才清空輸入。可拖放、⌘V 或用 📎 新增最多 10 張 png/jpg/jpeg/webp/gif/heic 圖片，按 × 取消，也可只傳圖片。在作業資料夾的 attachments/<作業ID>/ 保存原圖，必要時複製為 PNG；Claude 收到 Read 指示，Codex 收到 exec -i，Agy 收到圖片位置。GIF 使用第一格轉成的 PNG。Discord 沒有傳送功能，因此保存請求與圖片位置，並在作業畫面顯示尚未傳送及手動交付說明。需要詳細設定時，使用「＋ 設定細節並新增作業」。
- **對話欄圖片預覽**：拖放或 ⌘V 加入圖片後，請求上方會顯示縮圖。傳送前可按 × 取消，也可只傳圖片。切換畫面、重新繪製或傳送失敗時保留附件（重新啟動後只有「開始」欄會還原）。傳送時將圖片位置附在請求中；其他檔案仍將路徑寫入本文。
- **工作中的指示**（對話畫面）：AI 執行中輸入文字，可選［① 取消並重做］、［② 補充說明（一起處理）］或［③ 結束後接著做］。③ 可排隊依序自動開始，會保存並跨重新啟動保留；停止時可按［▶ 開始］傳送。［停止］也會取消等待中的指示。
- **新專案**：左側清單底部的［＋ 新專案］。輸入名稱、說明與階段（主資料夾、父專案、關聯在「詳細」中），便會建立專案紀錄、AI 指示與工作資料夾。

## AI 帳號

Gemini（Agy CLI）可在預設列按［確認狀態］。透過訂閱／免費額度的認證方式查詢 `agy models`，只有傳回核准模型才顯示已登入。API 設定不在適用範圍，無法判斷或逾時則顯示未確認。由於只在 Mac 鑰匙圈儲存一筆登入資訊，不提供額外帳號。［登入］、［登出］會在 Terminal 開啟 Agy，由本人輸入 `/login` 或 `/logout`。

ChatGPT 列的［開啟 ChatGPT］，在 App 會開啟旁邊的 ChatGPT，在瀏覽器則另開 chatgpt.com 分頁，請在該處登入。Hub 不處理認證資訊，也不確認其登入狀態。

角色分工可選經狀態確認已登入的 Claude Code、Codex、Gemini、Grok（包含額外帳號，不含 ChatGPT）。開啟 AI 分頁時，若未確認會查詢一次，也可［再次確認］。未安裝、未登入、API 認證或未確認的項目不能選，但已儲存或編輯中的負責設定會保留。Gemini 也從 Hub 確認的最新清單選模型，思考使用「高」。角色選 Gemini 後，給 AI 的模型與委派指示也會跟隨變更。儲存角色時不執行認證操作。

Claude Code、Codex、Grok 可在設定「AI 帳號」命名並［新增］。目前登入作為「預設」，沿用原有環境變數、設定與認證。新增後按［登入］會開啟 Mac Terminal，請本人登入訂閱帳號，再回來按［確認狀態］。不要在 Hub 輸入密碼或 token。［登出］經確認後執行 CLI 登出；預設帳號也會影響 Hub 以外的同一 CLI，因此會再次確認。

有多個帳號時，作業對話的 AI 選擇旁與終端機上方會顯示帳號選單。依作業與 AI 儲存，可在不同作業平行使用不同帳號。儲存選擇期間，對話傳送及內外終端機啟動會等待；完成後將確定的帳號附在請求中。儲存失敗則回復先前選擇，保留草稿。換帳號時不恢復舊會話，而是交接人與 AI 的文字。執行中對話與已排隊指示繼續使用受理時的帳號。同作業、同 AI 的內嵌終端機執行中時不能切換。帳號使用中、排隊中、認證操作中，或正在查詢狀態與使用額度時，不允許登出及刪除。

專案紀錄的 `_hub/accounts.json` 只保存名稱與位置。額外帳號放在 Documents 以外的 `~/.hub-accounts/<claude|codex|grok>/<id>`，權限為 0700。Claude 的 `CLAUDE_CONFIG_DIR` 與 Codex 的 `CODEX_HOME` 會傳給所有啟動方式。額外帳號排除從父程序或 Terminal 繼承的 OAuth／session token、認證 FD／檔案、主機認證及 `CLAUDE_SECURESTORAGE_CONFIG_DIR` 等認證覆寫；預設帳號則保留這些環境。Claude Code、Codex 會繼承一般設定及 CLAUDE.md／AGENTS.md，不複製認證、對話、MCP／外部連線、hooks／API／provider 設定。Grok 連設定檔也不複製。額外 Codex 會在啟動參數指定 `cli_auth_credentials_store="file"` 與 OpenAI provider，預設帳號的儲存方式不變。額外帳號所需外部連線與設定請本人另外處理。

［刪除（移至垃圾桶）］會將額外帳號整個位置移到垃圾桶。單純刪除不會登出 Claude 在 Mac 鑰匙圈的項目；若也要解除認證，請先［登出］。使用已刪除帳號的作業，下次啟動前須重新選取。Agy 只有預設帳號，角色檢討時只能將原本已由 Agy 負責的角色改用最新清單中的模型。

## Project Hub 自動更新（Git 原始碼環境）

以下是原始碼版的更新機制，不是發佈頁所提供封裝 App 的更新說明。

預設關閉，在設定「Project Hub 自動更新」切換。只有尚未儲存設定時，才以 `HUB_AUTO_UPDATE=1` 作為初始值，已儲存設定優先。

更新來源是 `kieiken/project-hub` 的 `main`，最多每 24 小時查詢一次。通訊前就保存查詢時間，失敗、手動要求或重新啟動都不解除限制。［立即檢查更新］在期限前也只顯示已保存結果。設定與紀錄放在 `HUB_ROOT/_hub/updates/`。

需要 macOS、已提交的 Git 原始碼絕對路徑（`HUB_UPDATE_SOURCE`）、目標 `Project Hub.app` 絕對路徑（`HUB_UPDATE_APP`）與 `HUB_STORAGE_GUARD`。設定不完整時顯示「尚未支援」。一般原生 App 會將原始碼與 App 位置傳入啟動環境。ZIP 原始碼等沒有 Git 歷史的環境不能使用。磁碟檢查失敗時，停止通訊、儲存與更新。

在獨立 checkout 整合新版，完成依賴安裝、全部測試、App 建置與簽章驗證。AI、排隊指示（包括重新啟動前儲存的指示）、整理或 GitHub 操作尚未結束，或原始碼有未提交變更時，等待套用。套用前再確認原始碼與簽章，保留舊 App 與原始碼後才替換。失敗保留舊 App；替換中斷則依儲存紀錄復原。設定畫面本身不自動重新載入。原生 App 套用後，確認沒有 AI 與排隊指示，才重新開啟新版。

已導入繁體中文辭典與 locale 邊界（`HUB_LANG=zh-TW`，未設定時使用日文）。單純安裝辭典不啟動自動翻譯或翻譯 PR。若要啟用，需有已用訂閱登入的本機 Codex（`gpt-6.1-sol`）、GitHub CLI（`gh`），並設定 `HUB_AUTO_TRANSLATE=1`、`HUB_TRANSLATION_FORK=<アカウント>/project-hub`（將佔位文字換成帳號）。不將按量計費 API 金鑰傳入翻譯程序。翻譯在隔離副本進行，不讀取個人專案紀錄。

PR 傳送到已確認的公開 fork 的 `automation/zh-tw`（可用 `HUB_TRANSLATION_BRANCH` 指定），以作者的 `main` 為目標建立或更新，不直接修改作者的 `main`。只傳送通過全部測試、建置、簽章與公開內容驗證的提交，並讀回確認 PR 目標、URL 與提交。翻譯及 PR 傳送也保存嘗試時間，失敗或中斷後最多每 24 小時重試一次。PR 傳送失敗與 App 套用狀態分開顯示。只有使用者啟用自動傳送才會執行，未啟用就不傳送。AI CLI 本身仍從「AI 更新」更新。

只有 App（window.swift）有變更時，才另外執行 `bash hub/app/build-app.sh`。

## 內部結構（開發者）

- **每次更新都調整版本**：`package.json` 的 version 與 `CHANGELOG.md` 最上方版本必須相同，否則測試失敗。新增功能調整第二段、僅修正調整第三段、大幅重做調整第一段。
- `server.js`：以 Node.js 執行，內嵌作業畫面使用 node-pty。只監聽 `127.0.0.1:4545`，不接受其他網站操作。
- `lib/frontmatter.js`：讀取專案紀錄開頭欄位；`lib/store.js`：讀寫專案紀錄與作業檔案；`lib/launch.js`：組合啟動指令；`lib/sessions.js`：內嵌作業畫面（node-pty）；`lib/roles.js`：讀寫角色分工；`lib/git.js`：建立、整合及整理工作副本。
- `public/`：畫面（`vendor/` 隨附 xterm.js）；`seed/`：初始專案紀錄；`test/`：`node --test --test-force-exit hub/test/*.test.js`。

修改「沒有變更」的顯示時，從儲存庫根目錄執行 `npm --prefix hub test` 與 `npm --prefix hub run test:langpack`。macOS 的 `TMPDIR` 要使用實體路徑。一般測試 `app-ui.test.js` 中的「実Git preview→UI」，會將主資料夾有未提交變更、以及相同 tree 尚未接收歷史的實際 preview 交給顯示程序，驗證初始隱藏、差異恢復、衝突、回應次序顛倒、重新繪製與定期查詢。顯示用的 `hideMainMergeControls` 以 `files === 0 && !conflict` 判定，不使用判斷能否安全略過整合的 `noChanges`。若要確認測試能抓出誤判，不修改實際檔案，只在隔離載入中將顯示條件替換成 `r.noChanges === true`，確認主資料夾未提交變更與尚未接收歷史的測試會失敗。不修改正式 API 與 Git 安全判定。

## 複製、刪除、整理與確認

對話框右上［複製］只複製內容。右鍵［刪除…］會先確認移到垃圾桶的項目，以及因共用而保留的項目。有 AI、排隊指示、子作業或工作副本時不能移動。可從［整理與確認］的紀錄還原，不覆寫同名檔案。專案紀錄與連結檢查只確認結構；App 運作則選擇既有測試指令來確認。

長步驟可在清單內捲動，按上方［收合步驟］關閉。

## 透過 CI 建立 Mac App

`.github/workflows/macos-app.yml` 先執行兩種語言的測試與公開內容乾式檢查，再組裝包含主程式的繁體中文 App 與 SHA256，供發佈使用。只有 `HUB_BUNDLE_RUNTIME=1` 時才將主程式、辭典、範本、範例放入 App。啟動仍需另行安裝 Node.js 22 以上及要使用的 AI CLI。一般建置仍參照原始碼位置。App 使用自行簽署的簽章，不進行 Apple 公證。

ChatGPT 的手動 Chat 與複製到 App 的路徑已移除。Chat／Pro 從 Hub 自動傳送，回覆儲存在同一對話。Chat／Pro 沒有操作檔案或執行指令的工具，給其他 AI 的實作許可也不適用。

整合後若顯示［重建 App］，請按下並依提示重新開啟。側邊 ChatGPT 面板已移除。
