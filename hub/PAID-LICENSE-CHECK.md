# Mac・Windowsの有料切替の隔離確認

この確認は、架空の利用コードを登録し、有料機能の許可と、登録したプロセスが終了した後の読戻しを調べます。購入・外部通信・AI実行はありません。本番やSandboxで購入した実際のコードは入力しないでください。

通常のデータとは別の新しい一時フォルダだけを使います。Macでは実際のキーチェーン、Windowsでは実際の資格情報マネージャー/DPAPIとローカルNTFS・SQLiteを使います。架空端末の鍵はランダムな `device-…` の別項目として残し、既存の鍵を読んだり消したりしません。Macは固定したSwiftソースをOS標準のSwiftで実行するため、開発ツールが必要です。別のコンパイル済み `mac-native` があるフォルダでは止まります。自動インストールや管理者昇格はしません。Windowsの既存ACLも変えず、補助の新設専用フォルダの保護条件を維持します。

独立確認後に渡された展開済みフォルダで、Macは `hub/check-paid-license.command`、Windowsは `hub/check-paid-license.cmd` を開きます。両方ともNode.js 22.13以降、Windowsはx64が必要です。スリープや購入画面の操作は不要です。途中で止まったら、再実行せず同じ会話へ結果を返します。通常利用のHubを再起動する必要はありません。

次の順に一回だけ確認します。

1. 未登録では有料5機能と委任の受付が拒否され、基本機能は許可される。
2. メモリー内の隔離発行元で架空コードを登録し、購入済みと有料5機能・委任の受付許可を確認する。実際のAIには依頼しない。
3. 登録したプロセスを完全に終了する。
4. 別のプロセスで、OSの秘密保管とデータフォルダだけから同じ端末の購入済み権利を読み戻す。利用コード・端末秘密鍵・発行秘密鍵は渡さず、ネット接続も認めない。

最後に表示される `result.json` を同じ会話へ返してください。結果は成否、OS、ソースの指紋だけで、コード・鍵・端末識別子・例外本文を含みません。成否にかかわらず一時フォルダとOS内の架空端末鍵を自動削除しません。

これは実OS上の保存機能と利用権判定の確認です。アプリ画面での実コード登録、アプリ終了/起動、OS自体の再起動、署名済み配布アプリ、更新後保持、本番販売の受入は別に残ります。隔離試験の成功をこれらの成功に置き換えません。Windowsの本番受付は閉じたままです。

作成担当は `node hub/build-paid-license-kit.cjs <保存コミット40桁> <存在しない出力先>` で両OS共通の固定ソースから作れます。展開済み一式とmanifestを照合し、独立確認後に渡します。従来のWindows全体確認セットや既存結果は上書きしません。
