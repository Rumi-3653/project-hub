# 試験の起動

全体は `npm test`、対象だけは `node test/run.cjs test/対象.test.js` で実行します。公開・公式の書き出し内でも同じ入口を使います。日本語で実行し、外部通信・OS の端末鍵操作・実際の購入や認証を行いません。`node --test` の直接実行は使いません。

入口は macOS の `sandbox-exec` で子孫プロセスも含め外向通信・Keychain・認証画面の起動を拒否します。さらに試験専用の先行読込みで Node の外向 fetch/socket/UDP と本物の端末鍵の生成を拒否し、通常の `License.prepare` を止めます。ローカル HTTP と、明示して渡したメモリ内の鍵・仮の発行先で行う利用権試験は残します。実際の status/require/guard や製品の起動方法は変えません。

子プロセスに別の環境を渡しても先行読込みを引き継ぎます。読込みが欠けたり置換されていたら試験実行の直前に拒否し、OS の遮断が使えない環境でも未遮断では始めません。この Mac 用入口の他 OS 対応は未実装です。これは信頼する試験コードの事故防止で、敵対的なコードを実行する環境ではありません。

macOS の隔離内では、管理者用属性のある `/bin/ps` 自体が実行できません。そのため、試験の親がプロセス一覧だけを読み取って返します。受付可能なのは製品が使う固定の一覧形式と PID の開始時刻・端末だけで、任意のコマンドは実行しません。所有判定には実際の一覧をそのまま渡し、製品の判定を代用しません。親への接続は一時フォルダのローカルソケットだけで、試験終了時に閉じます。

この遮断では、PDFKit 用の `osascript`、setuid 属性の付与、二重の OS 隔離も制約されます。該当する実 OS 試験は理由付きの除外として残し、成功扱いにはしません。setuid は実際に属性が落ちた場合、二重隔離は OS の拒否が確認された場合だけ除外します。他の確認は継続します。

`npm run test:langpack` も同じ遮断入口を使い、入口の既定言語は日本語です。各言語パックの試験が必要な言語を自分で設定します。入口は `HUB_LANG` を引き継がないため、起動コマンドに言語指定を重ねません。言語パック専用の試験を実行する時期は、プロジェクトの方針に従います。
